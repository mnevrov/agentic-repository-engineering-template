# /develop — одна задача разработки

Цель: полностью завершить **одну** небольшую задачу с доказательствами.

## 1. Контекст

Прочитай `AGENTS.md`, `docs/INDEX.md`, `ROADMAP.md`, `TODO.md`, архитектуру, ADR и файл выбранной задачи.

## 2. До кода

Покажи человеку:

- ID и название задачи;
- критерии приёмки;
- затрагиваемые файлы/компоненты;
- уровень риска A/B/C;
- короткий план;
- способ проверки результата.

Для существенного/опасного изменения дождись подтверждения.

## 3. Реализация

1. Добавь тест или иной воспроизводимый проверочный сценарий.
2. Получи ожидаемое падение, если применяется TDD.
3. Внеси минимальную реализацию.
4. Запусти локальные проверки.
5. Не исправляй несвязанные проблемы в том же цикле.

## 4. Проверка

- самопроверка diff;
- независимая проверка с чистым контекстом;
- для B/C — усиленная проверка по `code-review.md`;
- для C — повторять review до отсутствия нерешённых критических/высоких замечаний.

## 5. Завершение

Проверь `definition-of-done.md` и сформируй evidence summary:

- команды;
- результаты;
- ссылки/файлы доказательств;
- непроверенное;
- остаточные риски.

Обнови задачу, ROADMAP/TODO и документацию. Один завершённый цикл — один осмысленный коммит.
