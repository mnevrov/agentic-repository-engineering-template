# Архитектурные инварианты

Инварианты — короткие правила, которые агент должен проверять перед любым существенным изменением.

Примеры ниже замените на свои.

## INV-1 — Направление зависимостей

Доменная логика не зависит от transport/UI/framework слоя.

## INV-2 — Авторизация

Проверка прав выполняется до операции с защищёнными данными и не делегируется клиенту.

## INV-3 — Секреты

Секреты не хранятся в исходном коде, fixtures, логах и telemetry.

## INV-4 — Миграции

Изменение схемы данных выполняется отдельной обратимо спроектированной миграцией.

## INV-5 — Наблюдаемость

Критические операции имеют достаточный контекст в логах/метриках для диагностики без раскрытия секретов.

## Как менять инвариант

Если задача требует нарушить или заменить инвариант, сначала создайте ADR и зафиксируйте причину.
