# Пример первого агентского цикла

Этот пример показывает, как использовать шаблон после создания нового проекта.

## 1. Завести задачу

```bash
./scripts/new-task TASK-1 "Настроить реальные команды проверки проекта"
```

В результате появится файл:

```text
docs/tasks/TASK-1.md
```

## 2. Дать агенту ограниченный контекст

Минимальный контекст первой рабочей сессии:

```text
Изучи AGENTS.md, CLAUDE.md, docs/INDEX.md, docs/process/development-cycle.md и docs/tasks/TASK-1.md.
Предложи план выполнения одной задачи. Не меняй файлы до подтверждения.
```

## 3. Подтвердить план

Перед реализацией человек должен увидеть:

- какая задача выбрана;
- какой у неё риск: A/B/C;
- какие критерии приёмки будут закрыты;
- какие команды будут использованы для проверки;
- какие файлы ожидаемо изменятся.

## 4. Выполнить задачу

Агент меняет только файлы, относящиеся к задаче. Для первой задачи обычно меняются:

- `Makefile`;
- `README.md`;
- возможно `docs/tasks/TASK-1.md` — раздел «Доказательства».

## 5. Провести независимую проверку

В новом чистом чате используйте `REVIEW_PROMPT.md` и передайте:

- текст задачи;
- diff;
- критерии готовности;
- результаты команд проверки.

Результат проверки сохраните в `docs/reviews/TASK-1-review.md`.

## 6. Записать телеметрию

```bash
python scripts/record-cycle.py \
  --task TASK-1 \
  --started 2026-08-20T12:00:00Z \
  --ended 2026-08-20T12:30:00Z \
  --result passed \
  --risk A \
  --model example-model \
  --review-rounds 1 \
  --evidence docs/tasks/TASK-1.md
```

## 7. Посмотреть сводку

```bash
python scripts/telemetry-summary.py
```

## 8. Закоммитить

```bash
git add -A
git commit -m "TASK-1 setup project checks"
```

## Главный принцип

Не надо пытаться автоматизировать весь проект первым промтом. Ценность шаблона появляется, когда каждый цикл мал, проверяем и оставляет после себя след в репозитории.
