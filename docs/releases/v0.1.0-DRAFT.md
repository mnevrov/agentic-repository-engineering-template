# Agentic Repository Engineering Template — v0.1.0

> **DRAFT — НЕ ОПУБЛИКОВАНО.** Этот текст предназначен для GitHub Release только после выполнения всех обязательных gate из [release playbook](../release/RELEASE_PLAYBOOK.md).

## Назначение

Шаблон инженерного процесса для управляемой разработки с агентами **OpenCode v2**. Репозиторий задаёт проверяемый цикл «Task → план → изменения → тесты → review → evidence → telemetry», а не предоставляет отдельную оркестрационную платформу.

## Возможности

- Greenfield-bootstrap через GitHub Template и одноразовый `scripts/init-project`, с защитой от повторной деструктивной инициализации.
- Стадийное подключение к существующим Brownfield-репозиториям без перезаписи их документов и CI.
- OpenCode v2 `/develop`, `/iterate`, `/adopt-existing` и `/grill-me`; роли discovery/reviewer; permissions с точными shell-allow правилами.
- Реальные fail-closed project gates: template требует настройки `make check` и `make test`, не создавая ложных PASS по нулевым тестам. `make test-integration` также остаётся блокирующим, пока downstream не реализует настоящие проверки.
- Git-backed telemetry и provenance-bound однократный cutover, с охраной истории от переписывания, alias/mirror подмен и обходов через Git grafts/merge (TEMPLATE-15).

## Подтверждённая совместимость

- OpenCode v2.2.5: positive config/agent discovery CI.
- OpenCode v2.1.2: intentional negative compatibility test (не поддерживается).
- Source template doctor, 144 template tests по сохранённому отчёту, downstream bootstrap smoke — подтверждаются GitHub Actions на exact SHA (см. [матрицу](../RELEASE_READINESS.md)).
- Pilot `mnevrov/agentic-template`: `make check`, `make test`, отдельный локальный Git-backed `make test-integration` — PASS на GitHub Actions. Этот компонентный E3 не равен OpenCode HOST/LLM E4.

## Ограничения

- Шаблон не содержит provider credentials или встроенного доступа к внешним моделям; корпоративный LiteLLM настраивается вне репозитория.
- Живой OpenCode/Human Gate, реальная модель, отдельный release-review exact SHA и политика защиты main требуют независимых доказательств. Green CI не заменяет эти проверки.
- Частные проекты должны самостоятельно определить integration/e2e-acceptance и параметры моделей.
- Сетевая Git identity используется как необходимая provenance-эвристика; не является криптографическим удостоверением (см. ADR-0001).

## Быстрый старт

```bash
git clone <your-new-repository-created-from-template>
cd <your-new-repository-created-from-template>
./scripts/init-project "Название проекта"
./scripts/repo-doctor --template
make test-template
# Затем настройте собственные make check / make test / make test-integration.
opencode
```

Полная инструкция: [docs/GETTING_STARTED.md](../GETTING_STARTED.md). Пример реального downstream: [Pilot](https://github.com/mnevrov/agentic-template).
