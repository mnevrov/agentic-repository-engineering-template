# AGENTS.md

Этот репозиторий разрабатывается короткими проверяемыми циклами.

## Перед любой задачей

1. Прочитай `docs/INDEX.md`.
2. Прочитай `docs/backlog/ROADMAP.md` и `docs/backlog/TODO.md`.
3. Прочитай релевантные архитектурные документы и ADR.
4. Работай только над одной явно выбранной задачей.
5. Если критерии приёмки не определены — сначала зафиксируй их.

## Обязательные правила

- Не меняй архитектурные границы молча. Для существенного решения создай ADR.
- Не смешивай несвязанные изменения в одном цикле.
- Не ослабляй тесты ради прохождения проверки.
- Не скрывай известные дефекты или непроверенные допущения.
- Не называй результат «проверенным», если была только статическая/локальная проверка.
- Для задач риска B/C требуется явное подтверждение человека до реализации. Для A подтверждение можно делегировать только явно в файле задачи; опасные или необратимые действия всегда требуют отдельного подтверждения.
- Секреты и реальные credentials никогда не коммитятся.
- Независимый clean-context review обязателен для завершённой задачи; если его нельзя выполнить, результат цикла не может быть `passed`.
- Каждая попытка разработки должна оставить append-only запись телеметрии; неуспешные и прерванные попытки не скрываются.
- Не выдумывай значения метрик: неизвестное остаётся `null`.

## Порядок разработки

Следуй `docs/process/development-cycle.md`, `docs/process/definition-of-done.md`, `docs/process/traceability.md` и `docs/process/telemetry.md`.

## Проверки

Команды проекта должны быть собраны в `Makefile`:

```bash
make check
make test
make test-integration
make test-template
```

Ненастроенный project gate обязан завершаться `NOT CONFIGURED` с ненулевым кодом, а не имитировать PASS. Если gate ещё не определён, зафиксируй пробел и не повышай уровень доказательства.

## Review

Используй `docs/process/code-review.md`.
Результат независимого review сохраняется отдельным артефактом в `docs/reviews/`. Для задач уровня C результат не считается готовым при наличии нерешённых P0/P1.

## Формат завершения цикла

В финале перечисли:

- что изменено;
- какие критерии приёмки выполнены;
- какие команды проверки реально запускались;
- какие проверки не запускались и почему;
- известные ограничения/риски;
- какие документы обновлены;
- путь к артефакту независимого review;
- `cycle_id` записи телеметрии;
- рекомендуемый следующий небольшой шаг.
